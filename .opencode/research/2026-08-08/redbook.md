## 1. Two-Process Model (Глава 1)

### Суть
Человек и AI — два сопроцессора с **разной архитектурой**, комплементарными силами и слабостями. Не «начальник→подчинённый» (вся когнитивная нагрузка на человеке) и не «человек→инструмент» (AI — просто быстрые руки). Оба думают, но по-разному.

### Матрица ответственности (из Red Book)

| Зона | Только человек | Только AI |
|------|:---:|:---:|
| Смыслы, связь с реальностью | ✅ | ❌ (галлюцинации) |
| Архитектурные решения (уровень смыслов) | ✅ | ❌ |
| Приоритеты задач | ✅ | ❌ |
| Чувство «что-то не так» | ✅ | ❌ |
| Память между сессиями | ✅ | ❌ |
| Глобальная когерентность | ✅ | ❌ |
| Генерация больших объёмов кода | ❌ | ✅ |
| Синтаксис тысяч API | ❌ | ✅ |
| Механический рефакторинг | ❌ (IDE ломается) | ✅ |
| Шаблонный код/тесты | ❌ | ✅ |
| Держать ВСЕ детали файла в «голове» | ❌ | ✅ |
| **Спецификации** | Формулирует идею, решение | Структурирует, ищет пробелы |
| **Код-ревью** | Проверяет семантику (ЧТО НУЖНО) | Проверяет формальности (компиляция/тесты) |
| **Отладка** | Формулирует гипотезу | Собирает логи/стектрейсы |
| **Документация** | Проверяет реальность | Генерирует по диффу |

**Ключевая роль человека:** владение когерентностью (согласованностью между итерациями).

## 2. Shared State: файлы как IPC (Глава 2)

### Суть
Файлы — **не документация, а протокол межпроцессного взаимодействия**. Единственный канал обмена состоянием человек↔AI. Разрушен — система перестаёт функционировать.

### Четыре требования к IPC

#### 2.1 Адресуемость (spec:// URI)
```
spec://<модуль>/<документ>#<секция>[.<подсекция>]
```
- Коррекция: 20 токенов вместо сотен
- URI создают граф зависимостей спеки↔код
- **Lost in the Middle** (Liu et al., 2023): критическое — в начало/конец, не в середину

#### 2.2 Атомарность
- Один коммит = одна spec-мысль
- Коммит привязан к spec:// пункту
- Человек верифицирует diff за минуту

#### 2.3 Протокол конфликтов
- WAL с пометками «НЕ ТРОГАТЬ» предотвращает коллизии
- Два писателя — человек и AI — через файлы

#### 2.4 Conventional Commits с контекстом
```
feat(oproto): degraded mode [FEAT-007]
Решения: ...
Отброшено: ...
Ограничения: ...
```

### Сравнение с work-log/sync-issues

| Аспект | Red Book | opencode_initializer | Совпадение? |
|--------|----------|---------------------|:-----------:|
| Файлы = IPC | Центральная концепция | work-log.md + sync-issues.md | 🟡 Механика есть, философия не артикулирована |
| URI-адресация | `spec://` с якорями `{#id}` | Нет | 🔴 Отсутствует |
| Атомарность | Коммит = spec-пункт | Conventional Commits без spec-привязки | 🔴 Нет привязки |
| Протокол конфликтов | WAL «НЕ ТРОГАТЬ» | sync-issues.md реактивен | 🔴 Нет превентивного протокола |
| Sync-from-Code | Человек→код→AI:diff→спека | Нет | 🔴 Отсутствует |
| «Не трогай» | `match_by_hash(): НЕ ТРОГАТЬ (issue #12)` | Нет | 🔴 Отсутствует |

**Инцидент этой сессии** (worker затёр live-конфиг) — классический пример: два процесса писали в один файл без WAL-блокировки и пометок «НЕ ТРОГАТЬ». Red Book предотвращает: AI читает WAL → ограничения → обходит защищённые зоны.

## 3. Архитектура памяти (Глава 3, preview)

### Иерархия (4 уровня)

```
Уровень 1: Голова (интуиция, вкус, внепроектный контекст)
Уровень 2: WAL (текущее состояние, часы-дни, ПЕРЕЗАПИСЫВАЕТСЯ)
Уровень 3: Спецификации (стабилизированные решения, месяцы, spec://)
Уровень 4: Код (артефакт, «как», не «почему»)
```

### Ключевые правила
1. **Нисходящая запись:** решение → WAL → спека → код
2. **Единственный источник:** на каждый факт — один spec://
3. **Видимость:** только файлы переживают обоих

### WAL — checkpoint, не лог
- ПЕРЕЗАПИСЫВАЕТСЯ (≤ 1 страница)
- «Доска, не журнал»: 3 строки, не 300
- Дата обновления — первая строка
- Раздел «Ограничения» — самый важный

### Структура WAL
```
# WAL — Project Continuation State
_Обновлён: 2026-03-05T18:23:00Z_
## Текущая фаза
## Ограничения (не нарушать без обсуждения)
## Что сделано
## Следующее действие
## Известные проблемы
```

### Решения, а не факты
«Таймаут: 600s» — факт (из кода). Решение: «600s потому что VPN false positives, измерено, отбросили адаптивный, пересмотреть при p99<100s» — НЕ восстановить. Каждое решение: **почему + что рассматривали + когда пересмотреть**.

### Sync-from-Code
Человек меняет код → AI: `git diff HEAD` → предлагает обновление спеки → человек подтверждает (30 сек).

### Сравнение с 37-wal.sh + MemoryLayer

| Аспект | Red Book | opencode_initializer | Совпадение? |
|--------|----------|---------------------|:-----------:|
| Иерархия | 4 уровня (голова→WAL→спеки→код) | wal.md/wal.jsonl + skills + MemoryLayer | 🟡 Нет явной иерархии |
| WAL = checkpoint | ПЕРЕЗАПИСЫВАЕТСЯ | wal.md ✅, wal.jsonl ❌ (append-only) | 🔴 JSONL растёт бесконечно |
| Структура | Фаза, Ограничения, Сделано, Дальше, Проблемы | Active Phase, Protected, Decisions, Next Step | 🟡 Нет раздела «Ограничения» |
| Решения vs факты | Почему + альтернативы + revisit-condition | decision+rationale, без revisit | 🟡 Есть rationale |
| Sync-from-Code | AI:diff→спека | Нет | 🔴 Отсутствует |
| Агент vs чат | Агент — императив, чат — грубый контекст | Не различается | 🔴 Унифицирован |

## 4. Ключевые тезисы

1. **Человек — владелец когерентности, AI — быстрый исполнитель.** Два сопроцессора, не начальник→подчинённый. Согласованность между итерациями — на человеке, НЕ делегируется.

2. **Файлы — это IPC, не документация.** Единственный канал. Требует адресуемости (spec://), атомарности (1 коммит = 1 мысль) и протокола конфликтов.

3. **WAL — checkpoint, не лог.** Перезаписывается, ≤1 страница. 5 вопросов: где мы, что нельзя трогать, что сделано, что дальше, о чём знаем. «Ограничения» — критичный раздел.

4. **Записывай решения, не факты.** Факт («600s») из кода; решение («почему 600s») — нет. Включай: почему, альтернативы, когда пересмотреть.

5. **Иерархия: голова → WAL → спеки → код.** Информация течёт сверху вниз. Единственный источник на факт. Только файлы переживают обоих.

## 6. Слабые места / Критика Red Book

1. **Неполнота:** Глава 3 — preview, главы 4+ не написаны. «Snaps» анонсированы, не раскрыты.
2. **Масштаб:** Соло-разработчик. Нет рецептов для команды 5+ с 10+ AI-агентами.
3. **Инструментарий:** Привязан к Claude Code. Codex/Copilot/Cursor не описаны.
4. **Формат WAL:** Перезапись = потеря истории. Компромисс: milestone commits + snaps.
5. **Нет quantitative metrics:** «Одна страница» — эвристика, без измерений.
6. **Протокол конфликтов** концептуален, не формализован (нет lock-файлов, merge-стратегий).
